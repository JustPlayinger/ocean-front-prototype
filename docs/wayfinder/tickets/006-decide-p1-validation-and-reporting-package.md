# Decide P1 Validation And Reporting Package

Labels: `wayfinder:grilling`

## Question

What validation/reporting package proves the P1 loop is meaningful enough for the project while staying honest about evidence boundaries?

The decision must settle:

- Which plots or tables are required: response window, multi-radius sensitivity, non-front control comparison, case cards, or UI screenshots.
- Which metrics are reported: lift, front-control contrast, multi-radius consistency, enhancement hit rate, missing-data rate.
- How many case events are enough for a first demo.
- What claims are allowed in slides/paper notes.
- What remains explicitly unproven until P2.

Recommended default:

Produce one UI screenshot set, one typical-event response window figure, one multi-radius/control comparison table, and a short caveat block. Claim "front-associated apparent fishing activity response was observed/not observed under this sample and method", not "fishery yield was predicted".
