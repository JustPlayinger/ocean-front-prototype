# 信息架构与交互规范（v1.0）

> 日期：2026-09-12
> 适用范围：`prototype-fishing.html` / `prototype-fishing.js`
> 目的：把「渔场作业」的真实决策顺序固化为界面层级，消除冗余与主次不清

---

## 1. 市场与用户需求调研（结论）

### 1.1 调研来源（可核查）

| 来源 | 关键事实 |
|---|---|
| FishTrack（消费级海钓预报 App，Surfline/Wavetrak）| 首页即"找鱼工具"：**无云 SST 图 + 叶绿素 + 真彩影像 + 流场/潮汐/月相 + 7 天海洋天气**；配套**收藏点、温跃层断点标记、航点/航线、离线图**；卖点原话 **"Save time and fuel"**（省油＝省钱，即可达性）；用户原话："SST 和海洋预报是我早上最先看的两样东西……水温断点和风/流读数决定我怎么过这一天" |
| NOAA CoastWatch 产品检索 | 锋面是**业务化产品**：`ACSPO 0.02° Super-collated SST and Thermal Fronts (L3S-LEO)`，分辨率 2 km+，时效 NRT ≤24 h；另有**叶绿素异常产品**（相对 61 天中位数），说明"锋面 + 叶绿素边缘"可直接上图 |
| NOAA TurtleWatch（太平洋岛屿）| 典型的"**锋面直接产出空间指引**"形态：用特定 SST 等温线/锋面 + 水深界线圈定可用海域（具体阈值待核实）|
| Global Fishing Watch | 定位为**捕捞活动/热点 + 管辖区图层**（事后活动分布，属"验证类"信息，非"明天去哪"的预判）|
| OpenAlex 文献检索 | ① *SST fronts affect distribution of Pacific saury*（2014，被引 56）——锋面→物种栖息分布；② *Forecasting Albacore Fishing Grounds … ML + Ensemble*（2023）；③ *Ensemble Modelling of Skipjack Tuna Habitats*（2020，被引 51）；④ *Towards a Fishing Pressure Prediction System for a Western Pacific EEZ*（2019）；⑤ *Marine heatwaves redistribute pelagic fishing fleets*（2024）——**异常年份整体改变作业分布**；⑥ *Fishing for what? understanding fisher decision-making*（2010）——渔民决策＝经济+社会+环境混合；⑦ *Smartphone application use in commercial wild catch fisheries*（2022）；⑧ 东海相关：*Swordtip Squid Habitat（ECS, 2023）*、*Largehead Hairtail Nursery Grounds（ECS, 2022）* |

> 抓取受限（未取得内容，故不作依据）：`roffs.com`、`ripcharts.com`、`bom.gov.au`、`nmefc.cn`、`oceanguide.cn`、`eastfishery.ac.cn`、Bing/DuckDuckGo。中国本土"渔情速报/渔场预报"产品细节**暂无一手证据**，下文涉及处均已标注推断。

### 1.2 用户决策链（UI 层级据此排序）

```
第 0 问  今天/这几天能不能出海？   ← 安全（风/浪/涌）+ 成本（油）+ 法规（禁渔期）
第 1 问  去哪一片？              ← 渔场线索排序（锋面/温跃层/叶绿素边缘）+ 方位 + 距离
第 2 问  怎么去、多久到？         ← 航距 → 航时/油耗
第 3 问  什么时候最合适？         ← 未来 1/3/7 天窗口 + 逐日变化
第 4 问  为什么推荐这儿、可靠吗？  ← 历史同期规律 + 算法依据 + 异常提示
```

### 1.3 需求分级

- **Must**：结论先行的一句话建议；可执行点位（方位+距离）；可达性（航时/油耗）；时间窗；安全/海况；可解释依据
- **Should**：历史同期规律与异常提示；目标鱼种相关权重；图层可控 + 时效标识；无数据时的诚实回退
- **Could（本期不做）**：AIS 活动层、三维球面、离线包、分享导出、真实大模型

## 3. 目标信息架构（三层）

### 3.1 层级与职责

| 层 | 位置 | 职责 | 约束 |
|---|---|---|---|
| **L0 全局上下文** | 顶栏 | 定位点、作业半径、目标鱼种、时间条 | **全局唯一真源**；其它位置不得再出现时间/范围控件 |
| **L1 结论层** | 侧栏顶部 hero | 一句话建议 + 首选/备选点位 + 依据折叠 | 常驻，**不随页签消失**；无数据时明确说明且不给结论 |
| **L2 分层细节** | 页签 | 现在 / 未来（主任务）；规律 / 依据（支撑） | 主任务页签字号 13px+主色下划线；支撑页签 12px+弱色（视觉分层） |

```
┌────────────────────────────────────────────────────────────────────────────┐
│ L0  ⛵渔场向导  📍定位  [半径 10|20|30]  鱼种▾        [◀ 2024-08-05 ▶] [观测|预报|气候] │
├───────────────────────────────────────────┬────────────────────────────────┤
│                                           │ L1  今日建议（hero 常驻）        │
│              主地图                        │   ✔可出海 / 首选点位 / 依据 ▾     │
│  SST·等温线·锋面·冷暖侧·渔场区·半径环·定位点   ├────────────────────────────────┤
│                                           │ L2  现在 | 未来 ┄ 规律 | 依据    │
│  [图例·图层开关]              [＋ － ◎]     │     卡片流（随页签切换）          │
├───────────────────────────────────────────┴────────────────────────────────┤
│ 数据为演示占位 · 时次 …                                       口径与依据 ↗    │
└────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 页签主次与边界

| 页签 | 层级 | 回答 | 卡片构成 | 明确不做 |
|---|---|---|---|---|
| 现在 | 主 | 这里现在是什么情况 | 关键指标 4 格 / 海况与适航 / 范围内锋面清单 | 不做历史统计、不重复给建议 |
| 未来 | 主 | 未来 1/3/7 天怎样 | 1/3/7 天可能度 / 逐日窗口与最佳窗口 | 不给"最佳点位"（由 L1 负责） |
| 规律 | 支撑 | 同期规律如何 | 出现率（统一口径）+ 周期锚点 / 多年同期与异常（折叠） | 不使用第二套时间真源（仅本页锚点） |
| 依据 | 支撑 | 依据与可信度边界 | 数据来源与时次 / 判定规则与口径 / 局限与待接入 | 不再重复结论（原「AI 分析」的结论已上移 L1） |

## 4. 交互规范（9 条）

1. **单向数据流**：`state`（唯一真源）→ `render*()`；渲染函数只读 state，不写 state。所有状态变更集中在事件处理器内。
2. **单一选中语义**：`state.select = {type, id}`；地图要素、结论卡点位、列表条目共用同一选中态（`data-type/data-id`），任何位置点击同一条目结果一致；再次点击取消。
3. **几何同源**：定位点到锋面的距离/方位由经纬度折线实时计算（`nearestOnSegment` + `bearing16`），地图几何与卡片数值不允许出现两套数据。
4. **时间模型**：`state.time = {family, date}`，族语义固定 —— 观测（覆盖期 2024-06-01~2024-09-30）、预报（滚动 7 天窗口，越界自动收敛到今天）、气候（多年同期）；页签切换**不产生**第二套时间控件。
5. **范围模型**：`state.range` 唯一；半径环、范围内判定、回退规则、文案全部从它派生。
6. **反馈分工**：Toast 只用于"操作确认"（图层/定位/时次）；数据结论一律落在卡片，不用 Toast 播报结论。
7. **渐进披露**：卡片默认只给结论 + 一行依据，细节收进「依据与判定规则 / 多年同期与异常」折叠区。
8. **空态与回退**：无数据必须说明原因（覆盖期/窗口）且不给结论；半径内无命中时回退最近对象并**显式标注**"已回退"。
9. **可访问性与一致性**：页签 `role=tab` + `aria-selected`，支持 ←/→ 方向键；卡片术语与地图图例同名（SST/锋面线/冷侧·暖侧/渔场高概率区）。

## 5. 状态模型（`prototype-fishing.js`）

| 字段 | 说明 |
|---|---|
| `lon, lat` | 定位点（L0） |
| `range` | 作业半径 km，取值 10/20/30 |
| `species` | 目标鱼种 key，决定适温区间与冷暖侧偏好权重 |

## 6. 关键判定规则（与「依据」页同源）

| 项 | 规则 |
|---|---|
| 适航 | 风力 ≤5 级且浪高 ≤1.5 m ⇒ 适航；≤6 级且 ≤1.8 m ⇒ 临界；否则不适航 |
| 结论三档 | 不适航 ⇒ 暂缓出海（安全优先）；适航且可能度 ≥60% ⇒ 可出海；其余 ⇒ 谨慎出海 |
| 可能度 | 30 基础分 + 范围内锋面×12（≤3）+ 冷暖侧匹配（+15/−5）+ 梯度（±8）+ 范围内渔场区（+15）+ 适温匹配（+12/−6），clamp 至 5–95 |
| 出现率 | 窗口内有锋面天数 / 窗口内有效天数（**唯一口径**） |
| 未来可能度 | 当日可能度 × (1 − 6%×天数) × (1 ± 9% 扰动)，原型口径待回测校准 |
| 航时/油耗 | 距离 ÷ 14.8 km/h；距离 × 1.6 L/km（量级参考） |

## 7. 验收清单（已自动化，Edge 无头 + CDP）

| 类别 | 断言 |
|---|---|
| 结构 | 顶栏唯一日期控件、无 month/number 时间控件（消除双轨）、分段按钮 6 个 |
| 层级 | 主任务页签 = 现在/未来，支撑 = 规律/依据，默认落"现在"，页签互斥显示 |
| 结论层 | 结论三档文本、结论行含方位/距离/航时、首选点位 ≥1、依据分项 |
| 现在 | 指标 4 格、锋面清单 3 条、半径/鱼种标签与真源一致 |
| 未来 | 1/3/7 天口径文案、逐日 7 条 + 7 柱、最佳窗口 |
| 规律 | 按月 12 柱 / 按年 7 柱、统一口径文案、异常提示、仅 1 个锚点控件 |
| 依据 | 数据来源 7 行 / 规则 6 条 / 局限 4 条 |
| 联动 | 点击点位 → 地图压暗（0→3）、点位与地图共用选中态、图层开关真实重绘（rect 1→0→1） |
| 边界 | 超覆盖时次 → 地图+面板双空态且结论为"无数据"；预报族越界自动收敛 |
| 其他 | 鱼种切换改变可能度/结论、方向键切页签、无运行期 JS 异常、1680/1280 无横向溢出与文字裁切 |

## 8. 待确认问题

1. 主用户优先级：近海小渔船（日航次，重安全/成本）优先，还是远洋/专业捕捞（重鱼群定位）优先？
2. 「AI 分析」是否必须作为独立页签保留（本方案将其拆为 L1 结论 + 支撑页「依据」）？
3. 目标鱼种清单是否固定为东海常见 4 种？是否需要按海区配置？
4. 是否保留顶栏 4 档时间尺度（单日/连续多日/整月/整年）作为显式控件？
5. 海况（风/浪/涌）是否有真实数据源？若有，应升为 L1 Must 并替换 mock。
