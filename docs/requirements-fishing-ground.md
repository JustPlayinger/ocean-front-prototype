## 1. 项目定位

**面向渔场作业的海洋锋面分析系统**：以海洋锋面为核心环境因子，向渔民/渔业管理者提供"渔场在哪里、何时去、风险如何"的决策支持。

系统回答三类问题：
1. 当前位置/目标海域，**现在**有没有值得关注的锋面与渔场线索？
2. 这一带**过去**（近 1 月/1 年/历史同期）锋面活动规律如何？
3. **未来**（短临/数日）锋面会如何演化、渔场可能性如何变化？

> 定位转变对照：v0.1 定位是"海洋锋面时空任务分析工具"（面向科研演示）；v0.2 定位转向"渔场作业辅助"，一切功能围绕"渔场决策"收敛。

## 3. 界面信息架构（首页/主工作台）

> v0.3 起改为**三层结构**：L0 全局上下文（唯一真源）→ L1 结论层（常驻）→ L2 分层细节（页签）。
> 详细规范与调研依据见 `docs/ux-spec.md`。

```
┌──────────────────────────────────────────────────────────────────────┐
│ L0 顶栏：① 从哪出发 · ② 找多远(10/20/30km) · ③ 出海日(◀ 日期 ▶)          │
├──────────────────────────────────┬───────────────────────────────────┤
│                                  │ L1 结论层（常驻 hero）：            │
│                                  │   可否出海 + 首选点位 + 为什么       │
│     主地图（二维，可缩放）           ├───────────────────────────────────┤
│   SST/等温线/锋面/冷暖侧/渔场区       │ L2 页签：                          │
│   /作业半径环/定位点/指针查询浮层      │   现在 · 未来 ｜ 往年同期 · 依据     │
└──────────────────────────────────┴───────────────────────────────────┘
```

**四条硬约束**
1. **时间与范围只有一处真源**（L0 顶栏）；卡片内不得再出现第二套时间/范围控件。时间维度只有"出海日"一个控件，"观测/预报"由页签决定（现在页=观测，未来页=预报）。
2. **结论先于细节**：L1 常驻，任何页签切换都不隐藏结论；结论必须可执行（方位+距离+航时）。
3. **无数据不编造**：缺数据时给明确原因与可行动作，不给结论（FR-7）。
4. **控件唯一性**：任一可调维度（时间/范围/图层）全站只出现一处（FR-16）。

### 3.1 右侧功能分区（四类功能保留，职责重新划分）

| 分区 | 层级 | 回答的问题 | 主要内容 | 明确不做 |
|---|---|---|---|---|
| ① 现在 | 主任务 | 这里现在是什么情况？ | 眼下情况（水温 / 距最近锋面 / 所处侧别 / 去这里的把握）、天气与海况、找鱼范围内的锋面清单（可点选联动地图） | 不放往年统计 |
| ② 未来 | 主任务 | 未来 7 天里哪天去？ | 逐日把握（7 柱 + 7 行，点一下就把"出海日"设成那天）、最好的一天、1/3/7 天说明 | 不重复给点位建议（由 L1 负责） |
| ③ 往年同期 | 支撑 | 往年这时候什么规律？ | 有锋面的天数占比（这一天 / 这个月 / 这一年）、和往年比偏高/正常/偏低 + 对你的意义 | **页内不得有日期控件**（锚点用顶栏"出海日"） |
| ④ 依据 | 支撑 | 数据从哪来、怎么算的？ | 数据来源、算法说明、现在还做不到的 | 不再重复结论 |

> 说明：v0.2 的「④ AI 分析」在 v0.3 拆分为两部分 —— **结论上移 L1**（"去哪/去不去"是最高优先级信息，不应藏在页签里），**可解释部分下移「依据」**；原「可信度」卡按 §3.2 删除。四类功能无一丢失。

### 5.2 历史概率统一口径（依据 9.3.md）
- 只保留一个口径：**该点/该范围在所选时间窗内出现锋面的占比**。
  `频率 = 窗口内有锋面的有效日期数 / 窗口内有效日期总数`
- 时间窗支持：连续 N 日、指定月份、指定年份、历史同期（多年同月同日）。
- 移除多重概率定义、覆盖可信度等复杂标签；注释中保留计算公式供查证。
- v0.5 落地情况：已实现「同一天 / 这几天 / 整月」三种口径；整月因只取了每年 3 天样本而明确显示「样本不足」，
  不做外推。实现文件 `data/clim/same-period.js`，页面直接展示 `method` 与 `sample_note`。
- v0.6 现状：单日地图图层扩到 2024-07-01 ~ 08-31 共 62 天；同期样本仍为 2015—2024 的 8 月 5—7 日
  （个别年缺 1 天，按「有效天数」算并写明抽样口径）。

- 组件按"当前/历史/预测/AI"分区拆分，降低单文件体积（现状 App.tsx 过大，影响维护）。

## 6. 预测（本期为"算法定义 + 原型验证"，暂缓产品化）

### 6.1 预测目标
未来 L 天（L=1/3/7）某格点/区域**出现锋面（进而作为渔场线索）的可能性**。

### 6.2 预测输入（多因素，与 9.3.md 一致）
| 因素 | 说明 |
|---|---|
| 过去情况 | 历史同期锋面出现频率（§5.2 口径） |
| 冷暖情况 | 近期冷暖侧结构变化、SST 距平 |
| 锋面强度 | `frontal_intensity` 与局地温度梯度 |
| （后续）流场/风场 | GLORYS12 / ERA5，数据到位后加入 |

### 6.3 方法建议
- 先建立基线：持续性（今天有锋面→明天概率）+ 气候态（历史频率）。
- 在基线上迭代规则/统计/机器学习模型，要求可解释、可回看。
- 创新点定位（9.3.md）：设计**综合过去、冷暖、强度等多因素的复合概率算法**，与单一因素基线对比给出提升。

### 6.4 验收标准
- 预测接口返回可解释的"未来 L 天概率场 + 依据说明"；
- 有离线回测（用历史日期切分验证），指标可复现。

## 7. 性能与体验（9.3.md："查找经度纬度时加载过慢"）

| 目标 | 场景 | 指标 |
|---|---|---|
| 定位首屏 | 输入经纬度后 | ≤2s 出当前视图核心图层 |
| 尺度切换 | 单日 → 整月/整年 | ≤3s 出聚合结果（命中缓存时 ≤1s） |
| 地图漫游 | 缩放/平移 | 无整页加载感，无数据时有占位 |
| 首包体积 | 生产构建 | 无明显大 chunk 警告（现状 1.2MB 需代码分割） |

优化方向（按收益排序）：切片/瓦片缓存 → 聚合接口 → 按需加载 → 前端分包。

   → **待定 + 许可风险**：Global Fishing Watch 公开数据为 **CC BY-NC 4.0（仅非商业）**，且是"作业时长"而非渔获量；
      若要走这条线，需先确认项目是否非商业 + 是否申请 API/商业许可。

   → v0.5 已按"离线可用"实现：数据是预生成文件 + `<script>` 引入，双击即可跑，不依赖在线底图服务。
5. 预测结果是否需要有可解释性展示（用于向渔民解释"为什么这里可能高产"）。
   → v0.3 已按"必须可解释"落地：L1「依据与判定规则」逐项列出加分项；结论口径写入「依据」页。

   → v0.4 已收敛：顶栏只留「出海日」一个日期控件，"观测/预报"交给页签（现在/未来），"气候"改名为「往年同期」并只出现在该页。若评审要求保留四档，会与"控件唯一性"（FR-16）冲突，需先确认取舍。
